# mongodb_db_user (Resource)

Provides a MongoDB database user. Each user has a set of roles that grant access to databases.

> **IMPORTANT:** The `password` argument is stored in the raw state as plain text. [Read more about sensitive data in state.](https://developer.hashicorp.com/terraform/state/sensitive-data) To keep the password out of state entirely, use the write-only `password_wo` argument (Terraform 1.11+).

## Example Usage

### User with a predefined role

```terraform
resource "mongodb_db_user" "user" {
  auth_database = "my_database"
  name          = "example"
  password      = "example"
  role {
    role = "readAnyDatabase"
    db   = "my_database"
  }
}
```

### User with a custom role

```terraform
variable "username" {
  description = "the user name"
}
variable "password" {
  description = "the user password"
  sensitive   = true
}

resource "mongodb_db_user" "user_with_custom_role" {
  depends_on    = [mongodb_db_role.example_role]
  auth_database = "my_database"
  name          = var.username
  password      = var.password
  role {
    role = mongodb_db_role.example_role.name
    db   = "my_database"
  }
  role {
    role = "readAnyDatabase"
    db   = "admin"
  }
}
```

### User with a write-only password (Terraform 1.11+)

`password_wo` is never stored in Terraform state. Change `password_wo_version` to rotate it.

```terraform
resource "mongodb_db_user" "user_wo" {
  auth_database       = "my_database"
  name                = "example"
  password_wo         = var.password
  password_wo_version = "1"
  role {
    role = "readWrite"
    db   = "my_database"
  }
}
```

### IAM (MONGODB-AWS) user for Amazon DocumentDB

For `MONGODB-AWS`, `name` must be an AWS IAM ARN, no password is set, and the user lives in the `$external` database.

```terraform
resource "mongodb_db_user" "iam" {
  auth_mechanism = "MONGODB-AWS"
  name           = "arn:aws:iam::123456789012:role/my-app-role"
  role {
    role = "readWrite"
    db   = "my_database"
  }
}
```

## Schema

### Required

- `name` (String) Username for authenticating to MongoDB. For `MONGODB-AWS` this must be a valid AWS IAM ARN (`arn:aws:iam::<account-id>:(user|role)/<name>`). Changing it forces a new user.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `auth_database` (String) Database against which MongoDB authenticates the user. Required for password users; set to `$external` for `MONGODB-AWS` users.
- `auth_mechanism` (String) Authentication mechanism: `MONGODB-AWS` (Amazon DocumentDB IAM authentication) or empty (standard SCRAM password authentication). With `MONGODB-AWS`, `password` and `password_wo` must not be set.
- `authentication_restriction` (Block Set) Restricts the client and server addresses the user may connect from and to. Maps to MongoDB's user [`authenticationRestrictions`](https://www.mongodb.com/docs/manual/reference/method/db.createUser/#authentication-restrictions) (MongoDB 3.6+). May be repeated; a connection is allowed if it satisfies any one block. The configured value is kept in state as written; the provider does not read restrictions back from the server. (see [below for nested schema](#nestedblock--authentication_restriction))
- `password` (String, Sensitive) User's password, stored in state as plain text. Mutually exclusive with `password_wo`; one of them is required for password users. See [Sensitive Data in State](https://developer.hashicorp.com/terraform/state/sensitive-data).
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) User's password, supplied via configuration and **never stored in state** (Terraform 1.11+). Mutually exclusive with `password`; requires `password_wo_version`.
- `password_wo_version` (String) Change this value to rotate the write-only `password_wo`. Write-only values are not tracked in state, so this is the update trigger.
- `role` (Block Set) A role granted to the user and the database it applies to. A role on the `admin` database can include privileges that apply to other databases. At most 1000 roles (Amazon DocumentDB's per-user cap). (see [below for nested schema](#nestedblock--role))

### Read-Only

- `id` (String) Base64-encoded ID of the user, in the format `auth_database.username`.

## Import

In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import) to import the resource using its ID:

```terraform
import {
  to = mongodb_db_user.example_user
  id = "dGVzdF9kYi51c2VyX3Rlc3Q=" # base64 of "test_db.user_test"
}
```

The `terraform import` command can also be used:

```shell
# The ID is the base64-encoded "auth_database.username",
# e.g. for user "user_test" in database "test_db":
printf '%s' "test_db.user_test" | base64
# dGVzdF9kYi51c2VyX3Rlc3Q=

terraform import mongodb_db_user.example_user dGVzdF9kYi51c2VyX3Rlc3Q=
```
